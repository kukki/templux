# 项目通用改进经审查反哺（T28）

#29/#1故事6、ADR0001/0002/0012/0029；复用[共享发布](shared-release.md)、[项目升级提案](upgrade-proposals.md)、[受控发现](update-discovery.md)。这是人工审查合同及可复跑隔离演练，不建立反向同步平台或模板对所有项目的写权限。

## 贡献资格与所有权

源项目先用项目所有的最小适配解决真实使用问题，保存精确共享版本/manifest/baseline、自身修订/文件SHA及实际证据。贡献必须可由另一业务复用；仅提取通用行为、可选配置/类型和必要测试，不把项目名称、业务规则/路由/数据/角色、运行.env、密钥、密码、私有日志或基线后的真实配置复制进模板。合成示例也标明来源，不能把业务命名改一遍就声称通用。

公共扩展点由包exports和已记录合同决定。项目可以组合公开元素/状态/配置，不能通过贡献覆盖核心认证、组织、授权、强审计、迁移、会话或插入测试登录/换票入口。涉及这些边界必须独立规格与安全审查；本票纯文本CopyButton参数没有这种权限。未知/不兼容配置明确失败，默认兼容，禁止随意文件覆盖或静默改变项目数据语义。

## 候选清单与审查门槛

候选是固定修订的可评审产物，至少包含：

- 问题在真实隔离项目中的页面/配置证据，来源共享准确版本与manifest SHA、项目自身基线和修订；合成数据或平台替代明确标注。
- 原项目变更清单，以及逐文件/片段“提取/改写/留在项目”的所有权映射；候选最小patch、文件SHA/模式、来源commit与差异基线。
- 公开API/配置默认值、异常语义、破坏性变化、目标最新稳定版本、兼容组合和不支持范围；项目文案/业务版本独立。
- RED→GREEN、类型/构建与按影响实际组件/页面证据；安全/脱敏/凭据/资源清理声明和真实局限，不能把fixture模拟当生产链路。
- 独立审查者对该准确候选的结论、发现与处置、复核修订、审批记录标识。作者自查不代替独立审查；任何实质变更令旧批准失效，必须补审。

维护者按Standards与Spec两个轴检查通用性/最小性、公开边界、默认兼容、状态/异步与无权限放大、证据真实性及所有权。审查可拒绝或要求继续留在项目；不因能自动merge而通过。只有实际独立结论接受对应候选，才将受审源码纳入后续模板版本。

## 版本与接收方

公共修复/改进针对**最新正式稳定发布**，不是为每个旧分支自动回补。当前正式稳定仅0.1.0；0.2.0-t26.1、0.3.0-t27.1是历史演练overlay，不当作最新稳定功能或隐式继承。T28隔离0.1.1-t28.1仅演练，须明确来源受审commit和版本overlay、精确manifest/包SHA、支持from边与原始baseline；不覆盖0.1或已有产物，不自动向外发布。

另一项目自行授权选择准确版本，基于其保存的baseline生成T26候选/patch/report，保留业务/config和独立业务version。它可以拒绝、延迟或人工处理冲突，不由贡献作者替它自动合并。审查采用时先在一次性副本真实apply完整patch+vendor，核对完整文件集合/字节/模式等价、安装组合与项目行为/适当构建页面，再由项目自行安排审批/备份/维护/部署。新baseline只在该审核采用副本中推进，不能先写原项目。

本票不授权git push、npm publish、外部registry/云发布、联系其它团队、全局计划任务或部署；演练的A/B均由当前任务明确授权的自有隔离项目。没有自动全量反向同步/自动apply命令。真实组织人工飞书验收仍单列，不用此元素演练替代。
