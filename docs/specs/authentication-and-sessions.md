# 认证与会话现行规范

本文汇总已确认决策；未决项不视为实现要求。业务权限范围由各新项目定义，不在模板中建设通用范围模型。

## 账号与角色

- 首版面向内部员工与受邀合作方，不开放公众注册。
- 不同组织分别部署；飞书认证按部署配置校验允许组织。
- 默认预定义管理员、普通用户两个角色；账号可持有多个角色，操作权限默认取并集，零角色不授予业务访问。新项目可扩展角色、互斥约束及授权方式。
- 首次启动飞书登录进入 Pending，经 CLI 授予角色，可授权为管理员；不自动将首位登录用户设为管理员。既有管理员建立后新用户的具体审批操作仍待细化。
- 已建立管理员后，常规网页及 CLI 管理拒绝停用或降权最后一个有效管理员，须先建立另一个有效管理员；首次 Pending 与 CLI 初始化不受此限制。并发校验和紧急恢复细节另定。
- 人员账号可以关联飞书和授权密码登录，也可只启用其中一种，共享状态、角色、禁用及审计归属。
- 首版仅管理员通过管理界面或 CLI 发起关联及启用密码，身份验证完成后生效；不按姓名或邮箱自动合并。绑定冲突处理与验证流程待设计。
- 人员密码修改统一由管理员通过管理界面或 CLI 重置，首版不提供人员自助改密或邮件短信找回；管理员重置密码后提升账号会话/授权版本，使重置前全部旧会话失效并重新登录（已核对三个项目的共通机制）。同一人员账号的飞书与密码方式共用版本，不保留旧飞书会话。
- 人员管理员重置的新密码采用系统随机生成（来源 Supplieroom/Catchouse，TypeSafe 90% 自动采用）；具体交付方式另行核对。

## 会话与权限变更

- 会话和撤销信息存 PostgreSQL；正常重启保留有效且未撤销的会话。
- 默认允许同账号在多个设备或独立浏览器会话同时登录，各会话分别超时，人员与 Agent 同类规则；账号禁用或权限版本变化使该账号旧会话全部失效。新项目可调整并发策略，同浏览器共享 Cookie 的标签页不视为独立会话。
- 普通退出登录只撤销当前浏览器会话，另提供明确的退出全部会话入口，撤销当前账号所有会话（含当前），不新增设备列表。共享当前会话的标签页也退出，关闭标签页不等于服务端退出。
- 数据库备份恢复成功后、重新开放访问前，全部恢复出来的旧会话失效，人员与 Agent 重新登录；数据库恢复不视作普通应用重启。
- 权限变化使旧会话失效，前端通过心跳等检查获知并要求重新登录；每次受保护请求核对数据库中最新会话撤销、账号状态及授权版本。权限变更提交后新发起请求不按旧授权放行，不匹配要求重登；不承诺撤销已执行请求或既有操作效果。
- 新项目自行处理业务范围，在需要重新登录时接入统一会话失效机制；模板不固化供应商、仓库或店铺字段。
- 人员最长会话默认 12 小时；默认连续 10 分钟无操作退出，闲置时长可由 .env 覆盖。
- 后台心跳不计为真实用户操作，不延长闲置期限。
- 可见且在线页面默认每 30 秒检查会话，允许 .env 覆盖；页面恢复可见或网络恢复时立即校验，不承诺后台浏览器精确调度。
- 服务端明确会话失效后立即结束前端登录状态，返回登录页并持续显示本次失效原因，不等待确认或倒计时，未保存提醒不阻挡退出。普通网络故障与会话有效时的业务权限不足不按会话失效处理。
- 授权版本更新机制、原因枚举及提示文案待细化；不沿用 Supplieroom 的 60 秒退出倒计时。

## Agent 账号

- 独立身份，关联责任人，使用人员相同的业务角色与服务端权限检查；默认无业务权限，管理员明确授权。
- 业务授权长期有效，直到撤销或禁用；不代表登录会话永久有效。
- DEV/UAT 支持 Agent 登录；PROD 默认关闭，可由部署管理员显式启用。
- CLI 创建账号及可重置密码，通过正常登录页完成真实认证，不增加专用短期换票入口。
- 默认闲置 10 分钟，独立 .env 项覆盖，不影响人员。
- 最长会话默认 12 小时，独立 .env 项覆盖，不影响人员；此项经 TypeSafe 97% 自动采用。
- 初始密码由 CLI 随机生成，写入指定受限文件，普通输出不打印明文，不静默覆盖已有文件；具体文件参数和权限待细化。此项经 TypeSafe 80% 自动采用。

## 密码登录失败保护

- 采用三个项目的共通能力：失败达到阈值后临时限制登录尝试，成功登录清理相关失败记录。
- 按来源 IP + 用户名组合分别计数与限制（用户已确认），默认失败阈值 5 次（三项目共通默认，直接采用）。
- 采用 Catchouse 时间策略：从该组合首次失败起的 15 分钟窗口内达到 5 次，从触发时起固定限制 15 分钟；限制期间不继续累计，成功登录清理该组合记录。
- 失败记录采用 PostgreSQL 持久化及事务并发控制方向（Skoope 来源模式，TypeSafe 97% 自动采用），按 IP+用户名键及已定 15 分钟策略适配。同库实例共享记录，应用重启保留未到期限；过期清理及限流配置合同继续细化，不复制来源账号级业务字段。

## 飞书配置术语核对

通过 Context7 获取飞书官方文档后，已确认应用长期凭据为 App ID 和 App Secret，租户标识为 tenant_key。环境配置建议沿用明确名称 FEISHU_APP_ID、FEISHU_APP_SECRET、FEISHU_ALLOWED_TENANT_KEY；这些是模板变量名称，实际 API 参数以最终认证协议版本为准。

app_access_token 是有时限的运行时凭据，不应作为长期手工配置的 App Secret 替代品；需要时由后端按官方协议获取。用户先前提到的 App Token、Tenant ID 在规范中以以上具体术语表达。

依据：[企业自建应用 app_access_token](https://open.feishu.cn/document/server-docs/authentication-management/access-token/app_access_token_internal)、[tenant_key 定义](https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token)。官方索引同时返回旧版与新版 OAuth 说明，实施前需确认所选协议及完整用户信息合同，不能直接照搬旧示例端点。
