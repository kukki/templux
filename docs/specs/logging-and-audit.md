# 日志与审计规范

## 已确认

- 运行日志结构化；关键操作保留审计，覆盖认证、账号、授权撤销、Agent 操作及维护管理。
- 首版提供管理员专用关键操作审计查询页，含查询、筛选与分页；管理员权限由后端校验。不内置导出，新项目可按需扩展。
- 运行日志通过 Docker 或 CLI 查看，预留外部日志平台接入能力；首版不提供运行日志网页浏览器，不要求部署外部日志平台。
- 宿主管理 CLI 的变更记录 CLI 来源、目标及结果，操作者标识可信度取决于宿主身份机制。
- CLI 默认人工文本、可选 JSON；JSON 模式结果与运行诊断分开输出，凭据不打印在普通输出中。
- 审计默认保留 90 天后自动清理，允许配置覆盖；运行日志容量轮转并限制总量，以约 14 天为目标，容量先到可能更早淘汰，不承诺完整保留 14 天。
- 账号、角色、登录方式关联等关键数据库管理变更，必须可靠保存审计才算成功；审计保存失败则不提交变更并返回明确错误。这不规定登录失败事件、普通运行日志及停服救援操作的失败行为。

- 密码登录时，账号和会话核验正常、但成功登录审计单独写入失败，仍允许登录并记录运行错误；不声称审计已经保存，不允许数据库整体不可用时绕过认证。不改变关键管理变更的强审计要求。

## 待确认或细化

- 运行日志具体容量上限、留存配置项与清理执行机制。
- 审计查询条件、字段、分页及脱敏规则。
- 审计持久化设计，以及其它认证事件、运行日志与非数据库运维操作的记录失败行为。

本文件记录需求，不表示查询页面或存储已经实现。
