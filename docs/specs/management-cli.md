# 管理 CLI 规范

## 已确认范围

- 支持 Linux、macOS 的 Shell 入口；Windows 通过 WSL2 使用，不承诺首版原生 PowerShell 包装。
- 宿主依赖为 Docker、Compose 与基础 Shell，不要求 npm、Node.js、Java 或数据库客户端。
- 宿主脚本仅作容器入口包装、参数转交及退出码传递；交互菜单、应用参数解析、校验和实际操作均在容器内执行。
- 无参数时提供人工交互菜单，不必记忆参数；完整参数的一行脚本支持获授权 Agent 自动化运行。两种入口共用命令及校验逻辑。
- 无参数且有交互终端时进入菜单；完整参数直接执行，并提供显式非交互模式。非交互或无终端时缺少必填参数立即报错，返回非零退出码，不等待输入；人工可显式选择交互补齐。
- 禁用账号、更改角色、重置密码等管理变更，人工交互先展示目标及变更摘要并确认；非交互须提供显式确认参数，缺少则报错并返回非零退出码，不等待输入；只读查询无需确认。
- 默认人工可读文本，提供显式 JSON 模式供自动化解析；JSON 模式 stdout 仅输出结构化结果，运行日志与诊断写 stderr，退出码表示成功或失败。敏感凭据仍仅写受限文件。
- 获准执行管理容器并访问部署凭据的宿主运维操作者可执行管理 CLI，无需额外登录应用管理员账号；管理变更记录 CLI 来源、目标及结果，操作者身份的可信度依赖宿主身份机制。浏览器账号及 Agent 测试账号不因此获得宿主权限。
- 核心命令可在服务容器或一次性管理容器执行，不依赖 Web 服务已运行才能初始化。
- 统一启动/升级命令在应用启动前执行数据库迁移及结构校验，通过后启动，失败中止本次部署；Web 进程不自行修改结构。已有数据库存在待迁移项时默认先备份，失败中止迁移；全新空库和无待迁移项时跳过此前置备份。外部已备份时可显式提供备份参考并写入升级记录后跳过重复备份，不将自报参考视为模板已验证备份。
- 初始飞书 Pending 账号可通过 CLI 授予角色；CLI 支持创建独立 Agent 账号及可重置密码。
- Agent 初始随机密码写入指定受限文件，普通输出不打印明文，不静默覆盖已有文件；本规范不包含实际凭据。
- 维护通知的开始、取消和结束须衔接运维流程；通知计时到点不自行停服。
- 提供容器内数据库备份、恢复命令，支持人工菜单与 Agent 一行调用；恢复遵从显式确认规则。定时调度及异地存储由部署环境或新项目负责，模板不内置定时备份服务。

提供自动化入口不改变执行者的授权；浏览器中的 Agent 账号角色与受控宿主上的管理命令权限需要明确区分。

## 待细化

- 统一入口或分组脚本的命名和组织。
- 各命令参数、退出码分类及 JSON 结果字段。
- 管理审计的具体字段、宿主操作者标识及来源验证方式。
- 凭据文件路径、权限、容器与宿主文件归属。
- 完整命令清单及按平台验收。

本文件记录需求规范，不表示脚本已经实现或平台已经验收。

## T24 启动升级闭环

菜单1和`./templux start --json`复用同一备份→迁移→结构校验→应用启动链路。已有库/待迁移、外部参考、受限持久记录、宿主备份挂载投影和失败重试语义见[备份合同](backup-and-recovery.md#t24升级闭环与重试边界)，真实旧库及失败阻断见[T24验收](../discovery/t24-acceptance.md)。start失败不表示全批迁移回滚或既有运行进程已停；start成功也不替代维护模式明确恢复。

## T21 已实现维护入口

菜单18–24与maintenance-status/start/cancel/end/halt/resume/rescue共用容器参数/确认规则，版本和故障语义见[维护合同](maintenance-operations.md)。提醒持久化/强审计、独立entry、停写屏障与显式恢复已实现；不据此将后续备份恢复、升级任务标为完成。普通stop仍是包含入口与DB进程的全停并保留数据卷。

## T22 备份

菜单25和`backup --confirm --json`、迁移工具自动备份与显式外部参考已实现，见[备份合同](backup-and-recovery.md#t22-已实现容器备份与迁移前置)。手动输出区分备份、保留与临时清理结果；失败仍可能已有成功产物。T22当时未交付恢复CLI；T23更新见下方，自动调度仍未交付。

## T23 恢复

菜单26及 `restore --mode original|independent --target current|env:VAR --archive ABS --sha256 HEX --confirm --overwrite --json` 已实现，详见[恢复合同](backup-and-recovery.md#t23明确目标恢复)。模式/目标无默认；宿主包装器只作破坏性命令缺项前检和配置键转交，Docker前拒缺项，实际权限/身份/归档/恢复仍由容器统一校验。目标URL只通过受限环境提供，不放argv；`TEMPLUX_RESTORE_ADMIN_URL`可指定已存在救援库。未知完成不会自动重试或开放，恢复成功仍offline，须另一次明确maintenance-resume。自动定时/异地服务仍不属于此范围。
