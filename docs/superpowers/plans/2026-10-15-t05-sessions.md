# T05 Session Lifecycle Implementation Plan

> Native execution in shared workspace; independent review assigned by TL.

**Goal:** Persistent current/all logout, real idle enforcement and prompt session invalidation feedback across tabs.
**Architecture:** Shared advisory read locks coordinate SQL session/role snapshots with exclusive authorization/revocation mutations. Authenticated React pages mount a single session controller; heartbeat is read-only, trusted interactive events call an activity endpoint. Projects invalidate their own scope changes through an audited transaction interface.
**Tech Stack:** Existing TypeScript/Fastify/pg/PostgreSQL/Next.js/React; no new database objects needed.
**Spec:** Gitea #6/#1, authentication-and-sessions.md, ADR0020/0021/0023.

## Constraints and review focus

- Default12h/idle10m, Agent independent; HEARTBEAT_INTERVAL_SECONDS defaults30, bounded1–300.
- Every new protected authorization check after a committed mutation reads current state/version/revocation and roles together; no promise to undo already authorized operations.
- Heartbeat never touches activity; protected interactive API requests and explicit trusted input activity do. Hidden/offline polling pauses; visibility/online restoration checks immediately.
- Current logout revokes one session; all logout under the authorization lock revokes all existing account sessions, including current. Later deliberate login creates a new session.
- Business-scope invalidation accepts a checked-out transaction client after acquiring the authorization lock; caller mutates own scope and version/audit in that same commit. No built-in scope model.
- Explicit401 reason only causes immediate full navigation; normal403/network/5xx preserve login. Capture beforeunload suppression plus session-ending integration event lets project unsaved guards release; do not add T14 editing UI.
- Cross-tab event prompts server revalidation rather than trusting localStorage as authorization or ending a newer valid session blindly.
