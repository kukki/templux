# T28 reviewed contribution design

#29/#1 story6, ADR0001/0002/0012/0029. Latest formal stable is0.1.0; prior0.2/0.3 are test overlays, not stable releases. Project A and B consume exact0.1.0 artifacts in separate own directories. Existing shared-copy behavior, clipboard/security/session rules remain the implementation underneath.

A synthetic project workbench needs project-language copy action/pending/success/retry/failure feedback. Existing label only names the button for accessibility; the shared text is fixed Chinese. First implement and exercise a project-local adapter using public state/clipboard exports, then extract only a bounded CopyMessages plain-text default-merging helper and optional CopyButton messages prop. Project-specific text/route/brand and data stay project owned. Do not fork authentication or import private package paths.

Optional messages keys match the eight copy states/texts; defaults identical, unknown keys/non-string/empty/overlong rejected without echoing value. Partial overrides accepted, whitespace inside original strings preserved, no dynamic HTML/function callbacks/global language switch. Changing messages must not recreate store or restart pending/timer; values, writer, settings retain existing identity behavior. Labels do not grant authorization or validate clipboard success.

Candidate is a committed reviewable patch and source/hash/extraction manifest with tests and actual project A page evidence. TL must arrange a real independent approval; no producer/new template version before that conclusion. After approval, create only local test0.1.1-t28.1 with exact candidate commit and explicit version overlay; build through existing release-tools. B explicitly chooses it through T26, applies one complete patch+vendor to a disposable copy and validates full bytes/modes, project ownership, installed combination/build and page behavior. No automatic apply/deploy/push/registry/contact/global scheduler or business API/SQL.

Browser follows ego-browser first; own isolated TaskSpace only, record fallback if required. Synthetic component pages never authenticate or issue sessions; they are project-owned demonstration routes, never included in public package/template. Existing auth/SQL packages unchanged except shared new pure text helper bundled by normal build. Real credentials/database not needed for this scope.
