# Templux 首版任务拆分草案

父规格：https://gitea.whynots.top/Swython/Templux/issues/1

状态：用户已批准，29项已发布为 Gitea #2–#30；T编号仍为拆分编号。

## 拆分原则

- 编号为本地草案编号，不是已发布 issue 编号。
- 每项包含可演示的行为和必要的容器内验证；仅在该行为需要持久化或后端时引入相应层。
- 控件示例按规格使用内存样例，不为满足纵向切片而新增示例业务 API 或数据库表。
- 引用父规格的确认规则和范围，不重新选择技术栈或默认值。未定实施细节在所属任务内设计并记录。
- 依赖仅列直接阻塞，不重复列传递依赖；同级任务须遵守已有公共合同，不额外建立全局串行链。
- 每项应能在一个新的 Agent 上下文完成；不将测试、文档或必要迁移推迟给最终验收。
- 当前没有应用代码，无需单独预重构任务。发布时不得修改或关闭父规格 issue。

## 各项验收草案

### T01：容器一键启动并显示真实服务状态

**交付**：操作者只用 Docker、Compose 和基础 Shell 即可启动独立前后端及数据库，在浏览器看到来自真实后端的服务状态，并通过同一容器管理入口查看结果。

**直接阻塞**：无，可立即开始

**父规格用户故事**：1、15、44、45、46、47、48、50

- [ ] TypeScript、Next.js、Fastify、PostgreSQL 和参数化 SQL 按规格贯通；空库经独立管理步骤迁移校验后启动，Web 不迁移，失败明确中止。具体版本锁定。
- [ ] 前后端独立构建，页面读取真实后端状态；本任务只开放无敏感信息的状态与入口，不提前公开账号、业务或示例。
- [ ] 宿主包装只转交参数及退出码，容器内实现启动和状态菜单、完整参数、非交互及 JSON 合同；缺参数不挂起，日志写 stderr，不要求宿主语言运行时或数据库客户端。
- [ ] 启动、失败部署、正常停止及容器内行为检查可重复执行；从本任务起提供测试入口和结构化基础诊断，不把验证留给最终任务。

### T02：复制模板后初始化项目品牌与呈现配置

**交付**：项目创建者复制源码后用菜单或一行命令初始化名称、品牌和配置，重启即可在独立运行的新项目看到自己的风格、页头页脚和文案。

**直接阻塞**：T01

**父规格用户故事**：4、16、17、18、62、65

- [ ] 明确配置合同、校验、敏感环境配置隔离及已有内容覆盖规则；已有呈现值改动只需重启，不重新构建；代码和新资产仍按规格构建。
- [ ] 浅色蓝色强调默认与其它项目配色方向通过同一设计变量机制验证；页头页脚随内容滚动、区域隐藏替换及版本版权配置生效。
- [ ] 通用文案集中管理，默认简体中文；管理时间默认 Asia/Hong_Kong 显示到秒，项目可改，不引入个人主题语言时区切换。
- [ ] 隔离复制出的新项目可启动，初始化失败和无效配置有明确结果；提供使用说明，不另做目录生成脚手架或引入来源业务数据。

### T03：飞书首登 Pending 与 CLI 初始授权闭环

**交付**：匹配部署组织的人员飞书登录后看到 Pending，宿主操作者通过 CLI 授予角色后可正常登录受保护页面；不匹配组织和未授权账号被拒绝。

**直接阻塞**：T02

**父规格用户故事**：19、20、21、22、23、24、25、49

- [ ] 实现经当前官方协议核对的飞书认证及部署允许组织校验，长期凭据和运行令牌分离；默认两个预定义角色、可扩展多角色并集，Pending 或零角色无业务访问。
- [ ] 账号、授权、持久会话与关键授权审计通过真实数据库贯通；管理变更和审计可靠保存，不可靠则不提交，敏感凭据不进入日志。
- [ ] 宿主授权的菜单和一行 CLI 可为首位 Pending 建立管理员；变更明确确认，已有管理员时保护最后一个有效管理员，不能在中间交付留下绕过入口。
- [ ] 提供正常登录、组织拒绝、Pending 拒绝、授权后访问及审计故障的容器测试；真实飞书组织验收另列有凭据步骤，不新增测试登录后门。

### T04：人员与独立 Agent 的真实密码登录

**交付**：操作者可受控创建人员密码账号及关联责任人的 Agent 账号，获授权账号通过正常登录页访问应用，Agent 在生产默认无法登录。

**直接阻塞**：T03

**父规格用户故事**：26、38、39、40、41、42、43

- [ ] 人员与 Agent 身份分离，创建、授权、认证和后端访问检查贯通，不开放公众注册，不复用员工凭据或提供短期换票后门。
- [ ] Agent 初始随机密码仅写指定受限文件，拒绝静默覆盖，普通文本、JSON 和诊断不泄露明文；账号关联责任人，创建时默认无业务权限。
- [ ] DEV/UAT 与 PROD 开关和角色授权分别生效；通过真实密码页登录并验证无权、普通用户及明确授予管理员的区别。
- [ ] 密码验证、凭据保存、登录关联基本合同及安全会话配置形成实施决策；验证成功登录审计单独故障不阻断认证、整体数据库故障不能放行。

### T05：会话撤销、闲置退出与心跳重登

**交付**：人员和 Agent 可以当前退出或全部退出；闲置、禁用及授权变化后旧会话被后端拒绝，在线页面自动返回登录并说明原因，正常重启保持有效登录。

**直接阻塞**：T04

**父规格用户故事**：29、30、31、32、33、34、35、36

- [ ] 每次保护请求检查最新持久会话撤销、账号状态和授权版本；CLI 授权变更使旧会话失效，提供项目业务范围接入的失效接口，不固化业务范围模型。
- [ ] 人员和 Agent 默认12小时、闲置10分钟及既定独立配置有效；可见在线30秒心跳可配置，恢复可见或在线立即检查，心跳不延长闲置。
- [ ] 当前退出和全部退出作用范围正确；有效会话正常重启保持，撤销不可复活；多设备独立会话可用，共享 Cookie 标签页共同退出。
- [ ] 明确失效立即回登录持续原因，不等倒计时，不受未保存提醒阻挡；网络故障和正常业务403不误退出；并发权限变更与新请求边界有集成验证。

**直接阻塞**：T05

**父规格用户故事**：23、24、25、30、39、43

- [ ] 管理页面到 API、数据库及审计形成完整路径；人员和 Agent 状态、角色、责任归属可清楚区分，不建设自定义角色或业务范围编辑器。
- [ ] 多角色并集、零角色无业务访问及项目互斥扩展可验证；审批/授予使账号在重新登录后获得正确访问。
- [ ] 网页和 CLI 同时降权或停用管理员也无法移除最后一个有效管理员；测试首次零管理员初始化不被此保护阻断。
- [ ] 未经授权的直接 API 同样拒绝；关键管理审计失败不提交，成功变更及时撤销旧会话，页面显示真实结果。

- [ ] PostgreSQL 事务处理并发计数，同库实例共享，重启保留未到期限制；时间边界、组合隔离、成功清理均有行为测试。
